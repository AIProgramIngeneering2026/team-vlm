# ADR-0004. Без аутентификации: доступ к заданию по неугадываемому id

- **Дата:** 2026-11-13
- **Статус:** принято

## Контекст и ограничения

В границах проекта нет аккаунтов, регистрации и авторизации (см. README, «Что точно не входит»). При этом клиент может запросить
задание, которого нет, или задание другого клиента, и ответ не должен раскрывать чужие данные. В заданиях лежат личные фотографии,
поэтому утечка id равна утечке открытки.

## Решение

1. Аутентификации в первой версии нет. Доступ к заданию определяется знанием его `id` (модель «секретная ссылка»).
2. `id` имеет вид `j_` + 32 шестнадцатеричных символа из криптографического генератора случайных чисел (UUIDv4 без дефисов,
   122 бита случайности). Последовательные или предсказуемые номера не используются.
3. Перечислить задания нельзя: эндпоинта `GET /jobs` нет.
4. Любой `id`, которого нет в БД или который не подходит под формат, даёт один и тот же ответ `404 job_not_found`
   с одинаковым телом, чтобы по ответу нельзя было отличить «нет такого» от «чужой».
5. Файлы отдаются только через API по `id`, прямого доступа к тому нет. Срок хранения ограничен (по умолчанию 7 суток).

## Рассмотренные альтернативы

- **API-ключ на каждого клиента.** Нужны аккаунты, выдача и отзыв ключей, привязка заданий к владельцу: это вне границ проекта.
- **Отдельный токен доступа к результату, не равный `id`.** Лучше разделяет «видеть статус» и «скачать результат», но усложняет API,
  а пользы без аккаунтов мало.
- **mTLS или IP-ограничения.** Привязывают сервис к окружению, не подходят для открытого API.

## Цена решения

- Любой, кто узнал `id`, видит статус и получает открытку, а отозвать доступ можно только удалением или истечением срока.
- Ключ идемпотентности тоже должен оставаться секретом клиента: повтор с тем же ключом и тем же содержимым возвращает задание,
  а при другом содержимом `409` не раскрывает `id` существующего задания.
- Нет журнала «кто что скачал».
- Фото людей могут оказаться персональными данными; смягчается ограниченным сроком хранения и отсутствием перечисления.

## Условия пересмотра

- Сервис выходит за закрытую среду или принимает фото третьих лиц в заметных объёмах.
- В проект добавляются аккаунты: привязать задания к владельцу, ключ идемпотентности делать уникальным в рамках владельца,
  добавить удаление по запросу владельца (`DELETE /jobs/{id}`).
