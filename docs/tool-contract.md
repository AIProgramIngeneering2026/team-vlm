# Контракт Tool

## Назначение

Tool — отдельная операция оформления открытки. Dispatcher выполняет операции из Job по порядку и получает Tool из Registry по значению поля `operation`.

Tool отвечает только за одну операцию над изображением. Он не создаёт Job, не управляет его статусом и не сохраняет итоговый файл.

## Общий контракт

### Вход

Каждый Tool получает:

- исходное изображение, полученное после предыдущей операции; для первой операции — проверенную фотографию клиента;
- параметры конкретной операции;
- контекст выполнения, предоставленный сервисом.

Параметры должны соответствовать схеме операции из `docs/api/openapi.yaml`. Значения по умолчанию применяются до вызова Tool.

Tool не должен изменять исходное изображение на месте: результат операции возвращается как новое изображение или отдельное значение, которым заменяется текущее изображение в Dispatcher.

### Результат

При успешном выполнении Tool возвращает:

- обработанное изображение;
- ноль или более предупреждений, которые не мешают завершить Job.

Dispatcher передаёт обработанное изображение следующему Tool. После последней операции он сохраняет результат и переводит Job в `done`.

### Ошибки

Tool может сообщить об ошибке выполнения, если не может завершить обработку, например из-за сбоя библиотеки обработки изображений.

Ошибка выполнения должна содержать:

- стабильный машинный код;
- сообщение для диагностики;
- индекс операции в списке Job и её имя — эти поля добавляет Dispatcher.

Dispatcher переводит Job в `failed`, сохраняет ошибку в `Job.error` и не запускает следующие операции.

Ошибки формы запроса и допустимости параметров не являются ошибками выполнения Tool: они возвращаются при создании Job до начала обработки в соответствии с контрактом API.

### Проверка параметров

Вызывающая сторона (слой валидации до создания Job) проверяет:

- что операция известна;
- что обязательные параметры переданы;
- типы, допустимые значения и диапазоны параметров;
- ограничения на число операций.

Если проверка не пройдена, API отвечает `422` с кодом `unknown_operation` или `invalid_params`; Job не создаётся. Tool может проверять предусловия, необходимые для безопасного выполнения, но не должен повторно определять публичную схему параметров или подменять ошибки валидации ошибками обработки.

## Контракт конкретных Tool

### `resize_crop`

**Параметры:**

- `format`: `a6` или `a5`; по умолчанию `a6`;
- `fit`: `crop` или `pad`; по умолчанию `crop`.

**Вход:** текущее изображение и валидированные параметры `format` и `fit`.

**Результат:** новое изображение размера открытки, выбранного по `format`. Ориентация выбирается по ориентации входного изображения. При `fit: crop` изображение обрезается по центру; при `fit: pad` оно помещается целиком на белый фон.

**Ошибки:**

- недопустимый `format` или `fit` отклоняется до создания Job с `422 invalid_params`;
- ошибка декодирования или обработки изображения после начала выполнения приводит к ошибке Job `processing_failed`.

### `frame`

**Параметры:**

- `style`: `thin` или `classic`; по умолчанию `classic`;
- `width`: целое число от 1 до 15 — процент от меньшей стороны изображения; по умолчанию `5`;
- `color`: цвет формата `#RRGGBB`; по умолчанию `#FFFFFF`.

**Вход:** текущее изображение и валидированные параметры рамки.

**Результат:** новое изображение с рамкой выбранного стиля, толщины и цвета.

**Ошибки:**

- недопустимые `style`, `width` или `color` отклоняются до создания Job с `422 invalid_params`; в `details` указывается поле;
- ошибка применения рамки после начала выполнения приводит к ошибке Job `processing_failed`.

## Ответственность компонентов

| Компонент | Ответственность |
|---|---|
| Слой валидации API | Проверить структуру запроса, наличие операции, параметры и ограничения до создания Job |
| Registry | Найти Tool по имени операции |
| Dispatcher | Запустить Tool в порядке списка, передать изображение и параметры, обработать результат или ошибку |
| Tool | Выполнить одну операцию и вернуть новое изображение, предупреждения или ошибку выполнения |
| Job-хранилище и файловое хранилище | Сохранять состояние Job и файлы; Tool не управляет их жизненным циклом |

## Связь с API

Публичные имена операций, параметры, значения по умолчанию и ошибки валидации задаются в `docs/api/openapi.yaml`. Этот документ описывает внутреннюю ответственность Tool и взаимодействие Tool с Dispatcher.

Добавление операции требует добавить её схему и ошибки валидации в OpenAPI, реализовать Tool и зарегистрировать его в Registry.
